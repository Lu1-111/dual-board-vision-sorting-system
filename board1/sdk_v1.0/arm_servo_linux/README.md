# PS 六轴机械臂控制（Linux / C++11）

固定外置相机、无传送带的单次视觉抓放入口见 [固定相机联调](FIXED_CAMERA_SORT.md)。包含可修改的相机假设、统一放置点及五类分区配置，假设参数仅用于模拟。

GPIO 通信、关节控制和机械臂运动学已拆成共享库，供 `armctl` 和 `../ui_app` 的 Qt 机械臂页使用。新增固定高度的 `RobotArm::previewXY()` / `moveXY()`，以及读取现有 NPU 检测 JSON 的像素标定桥接程序，见 [视觉 XY 定位说明](VISION_XY.md)。自动分拣与传送带联动状态机位于 `../ui_app`，共享本控制层。

| 文件 | 用途 |
| --- | --- |
| `arm_control.hpp/.cpp` | 轴号映射、方向、角度/微秒校准、配置读写、20 ms 非阻塞运动及停止 |
| `gpio_backend.hpp/.cpp` | GPIO 芯片身份检查、64 位命令提交；模拟后端不申请 GPIO |
| `kinematics.hpp/.cpp` | 正逆运动学、限位、俯仰搜索、正解回算 |
| `robot_arm.hpp/.cpp` | 夹爪、腕旋、显式复位、坐标运动 |
| `armctl.cpp` | 支持运动中停止和新命令的 Linux CLI |
| `arm_config.ini` | 未经实测确认的默认校准模板 |

旧的独立 `servoctl.c` 已移除，统一使用 `armctl` 与 Qt 共用的 GPIO、关节及运动学控制层。`release/servoctl-aarch64` 如仍存在，仅是历史二进制，不作为当前构建入口。

## 轴号、脉宽与运动

| 代码逻辑轴（0 起） | 参考舵机 ID / Qt 轴号（1 起） | 部位 | 默认 PL 通道 |
| --- | --- | --- | --- |
| 0 | 1 | 夹爪 | 0 |
| 1 | 2 | 腕部旋转 | 1 |
| 2 | 3 | 腕部俯仰 | 2 |
| 3 | 4 | 肘关节 | 3 |
| 4 | 5 | 肩关节 | 4 |
| 5 | 6 | 底座 | 5 |

MCU 内部数组从舵机 6 倒序排列；本实现用上表逻辑顺序，发送时按每轴 `channel` 映射。夹爪开合角 0..90° 转成舵机角 `90-open`，腕旋 -90..90° 转成 `90-roll`。普通配置默认夹爪脉宽上限 1500 μs，其他轴 500..2499.2 μs；这些范围需结合实机限位缩小。临时全范围调试开放六轴 500..2499.2 μs，见后文。参考复位脉宽 770/1500/640/511/1255/1500 μs 已转换为默认 home 角，复位仅在明确调用时执行。

PS 保存双精度角度和微秒值，后端才量化为 8 位码。实际步长 7.84 μs、端点 500..2499.2 μs。量化码还约束在校准物理范围内，避免舍入越界；默认夹爪最大实际输出 1495.68 μs。`offset_us` 是角度映射后的补偿，直接微秒接口使用物理脉宽，不重复加偏移。

`moveAngles()` / `movePulses()` 立即返回，用单调时钟每 20 ms 调度 `tick()`。新运动从最后发送的命令继续，`stop()` 取消插值并保持，`disable()` 关闭全部 PWM。读数是命令估计，没有位置反馈。PL 禁能在帧边界生效，延迟可达 20 ms；新后端等待 FPGA 确认接收并应用使能状态，30 ms 内未确认则锁定会话。

## 程序失联与重新使能

配合本轮更新的 PL，舵机看门狗默认在 1000 ms 未收到有效提交后保持最后已输出的六轴脉宽，并拒绝新的使能运动命令。必须先提交禁能，再重新确认初始命令并使能；PL 复位后也要求此握手。静止保持期间仍须持续调度 `Controller::tick()`，GPIO 后端每 200 ms 刷新一次相同命令。

软件在 750 ms 无成功提交时提前锁定会话，事件循环恢复、迟到心跳和新运动都不能自动恢复。Qt 状态和控制台 `holdingAfterTimeout` 会报告失联保持。`off` / 关闭 PWM 成功后才能重新使能。改变 PL 的 50 MHz 时钟或 `WATCHDOG_MS` 时，须同时核对软件时限。

程序退出、EOF、信号退出、页面切换、后端释放或重新连接均不自动禁能。重新连接先读取 FPGA 状态并锁定控制，不写入姿态或清除保护；必须显式执行 `off` / `disable`（Qt 的“关闭 PWM”），再确认六轴初始命令并重新使能。GPIO 写入或状态读取失败也锁定控制，避免错误清理流程撤销保持力。

PL GPIO 55..50 改为六位状态输入：`[5:4]=2'b10` 为协议标识，`[3]` 为已接受提交位，`[2]` 为实际 PWM 使能，`[1]` 为待应用使能，`[0]` 为保护锁定。对应 bank3 的 18..23 号线以输入申请，其余 26 根仍为命令输出。状态确认失败或旧位流返回无效标识时拒绝连接；不允许回退为无反馈输出。Qt 控制台新增 `hardwareStatusAvailable`、`hardwareOutputActive`；这些反映控制逻辑，不是舵机角度反馈。

命令标识由旧版 `0xA5` 升级为 `0xA6`。新 PL 拒绝旧命令，包括旧程序连接时自动发送的禁能；新程序也拒绝没有状态回读的旧 PL。必须配套使用本轮软件和 FPGA 构建，不混用历史发布文件。

后端先申请高 bank 的命令标识线，再申请其余命令线，避免 Linux 逐位初始化输出时意外提交旧命令。每次发送先准备两组数据并保持原提交位，再单独翻转提交位；不依赖内核批量 GPIO 写入具有原子性。

这里的失联指程序或通信停止、FPGA 与舵机仍正常供电。舵机断电后没有保持力，FPGA 断电后也不能继续产生 PWM；断电保持须由机械自锁、抱闸或备用供电实现。仍然没有实际位置或抓取反馈。新软件与新位流须配套验证，旧位流没有该硬件看门狗；本轮编译不自动部署。

## 构建与模拟

```sh
cd sdk/arm_servo_linux
make test
./build/armctl --simulate --config arm_config.ini
```

CLI 默认模拟，初始化禁能。示例命令：

```text
status
ack 770 1500 640 511 1255 1500 confirm
enable
angles 25 90 80 80 90 90 1000
stop
preview 15 0 2 -45
claw 45 500
roll 0 500
home 1500
off
quit
```

`angles` / `pulses` 接受六轴值与可选时间；`coord x y z pitch [ms]` 执行坐标运动；`fk` 显示当前命令正解。`ack` 声明由调用者核对的完整初始脉宽，不测量当前位置。运动中可输入 `stop`、`off` / `disable`、新目标或 Ctrl+C；EOF 和正常信号退出保留最后 PWM，不执行后续动作。

AArch64 构建：配套 Ubuntu VM 运行 `bash build_board.sh`，或设置 `TOOLCHAIN_BIN` / `CXX`；产物 `release/armctl-aarch64`。Qt 构建和动作 JSON 见 `../ui_app/README.md`。

## 硬件连接和逐轴校准

现有设备树 `gpio@f8411200` 和 `gpio@f8411300` 对应两组 32 路 GPIO；内核需启用 `CONFIG_GPIO_CDEV` 和 `CONFIG_GPIO_DWAPB`。运行 `armctl --list` 核对实际 gpiochip：

```sh
armctl --hardware --bank2 /dev/gpiochipN --bank3 /dev/gpiochipM --config arm_config.ini
```

后端验证字符设备、线数、两设备不同及 sysfs `of_node` 地址，运行时独占这两个 bank。默认 `calibration_confirmed=0`、各轴 `calibrated=0`、`geometry_confirmed=0`；普通硬件运动需先完成实测确认。

1. 每次连接硬件后先显式执行 `off` / `disable`，确认 FPGA 已禁能并解除控制锁定。再核对六个初始脉宽、接线和机械姿态，用 `ack ... confirm` 声明完整初始命令。PL 只有全局启能；单轴校准时其他五轴也收到已确认脉宽，不能独立只启用某轴。
2. `calibrate axis pulse_us ms confirm` 测试所选轴并保持其他轴。先从小范围变化确认方向与限位；每次 `off` 或控制错误后必须重新声明初始六轴命令。
3. 修改 `channel`、`direction`、角度范围、物理脉宽范围、偏移和 home，实测后标记该轴 `calibrated=1`。全部轴完成后设置 `calibration_confirmed=1` 并重新连接。
4. 实测四个连杆尺寸，修改 `link0_cm`..`link3_cm` 并设置 `geometry_confirmed=1`。先逆解预览，再试少量已知坐标。

配置严格解析完整 `key=value` 字段、格式版本、重复/未知键、有限值、映射和限位。保存采用同目录临时文件替换，失败保留原配置。Qt 页可编辑同一格式；硬件配置变化后需重新连接。

## 运动学和后续接口

默认连杆长度来自参考 `kinematics.h`（cm）：2.89/10.43/8.9/17.7。例程没有 `kinematics.c`，但 `Listings/kinematics.lst` 保留源行；据此恢复 FK 和角度定义，并重新实现双分支解析 IK。+X 向前、+Y 向左、+Z 向上，pitch 为肩/肘/腕俯仰角之和。先尝试期望 pitch，再在默认 -90..10° 内搜索最近可达解，检查关节限位和 FK 残差。

2026-10-23 增加可保存的尖端坐标原点。`RobotArm::zeroAtCurrentPose()` 在已使能且停止时，按最后命令的 FK 记录原点；此操作不发送 PWM。`previewCoordinate()`、`moveCoordinate()`、`currentCartesian()` 采用该相对坐标，`currentBaseCartesian()` 始终返回原基坐标。XYZ 只平移，俯仰仍是相对水平面的角度。常规/全范围调试映射不一致时拒绝相对坐标运动，避免解释错误；`setCartesianFrame()` 可恢复配置或清除原点。通过 `ArmConfig::cartesianFrame` 保存参考，旧配置不含该可选块时保持原有基坐标行为。`moveCoordinateWithTools()` 供坐标动作帧使用，在一次六轴运动中同时设置夹爪和腕旋舵机角度。

当前是关节插值和末端姿态求解，没有碰撞检测或笛卡尔直线路径规划。0.25° 俯仰搜索步长可能漏掉更窄可达区；数学残差不含 PL 量化、舵机和几何测量误差。

视觉定位可用 `tools/vision_xy.py` 将实测平面上的像素转换为当前机械臂坐标，再通过正在运行的 Qt 会话调用 XY 逆解。相机随臂运动时，须保持标定拍摄姿态，重新识别前先返回该姿态。该工具是单次定位入口，没有自动抓放和分拣状态机。

## 临时全范围调试会话（2026-10-16）

`Controller::enablePulseDebug(baseline, true)` 在明确确认六轴初始脉宽后启用临时调试。六轴（包括夹爪）均开放 PL 全范围 **500～2499.2 μs**；该入口允许夹爪初始值超过普通配置的 1500 μs 上限。原有 `enablePulseDebug(true)` 仍可在已确认初始命令后调用。全范围调试仅在当前会话有效，不修改 `calibrated`、`calibrationConfirmed`、几何确认或保存的校准参数。

调试期间，`moveDebugPulses()`、`movePulses()`、`moveAngles()`、单轴校准、夹爪、腕旋、复位和动作组均可使用；角度临时按每轴 0～180° 对应全脉宽范围，保留配置中的方向和通道映射，临时偏移为 0。坐标运动允许使用当前配置几何，即使几何尚未确认，仍检查有限数值、尺寸一致性、可达性及逆解回算。该映射和几何不代表已经完成实机校准。

核心运动最短 20 ms，最长 1 小时；Qt 和串口界面接受 20～60000 ms。最终输出仍量化为 8 位、步进 7.84 μs，不能超出 PL 数值范围。关闭或出错会清除调试授权并恢复原校准映射；`stop()` 只停止插值并保持 PWM。正常硬件模式仍要求原来的校准确认，不能把调试授权持久化成实测结果。
