# LeArm 参考姿态动作组（离线模板，2026-10-21）

本目录把项目内 LeArm 颜色分拣 C 程序改写成现有 Qt 界面可加载的 JSON 动作组。**格式转换已完成，实机运动尚未验证，不能当作已校准的生产动作直接播放。** 没有连接串口、GPIO 或板端控制服务，也没有修改实机配置、固件或现有界面程序。

## 文件选择

| 文件 | 内容 | 帧数 / 名义总时间 |
| --- | --- | --- |
| `00_reference_home.json` | 原厂复位脉宽对应的项目角度 | 1 / 1000 ms |
| `01_reference_ready.json` | 移到准备坐标，再张开夹爪 | 2 / 520 ms |
| `sort_red_50mm.json` ～ `sort_red_100mm.json` | 取物、抬起、红色左侧放置、返回 | 各 8 / 4720 ms |
| `sort_green_50mm.json` ～ `sort_green_100mm.json` | 取物、抬起、绿色右侧放置、返回 | 各 8 / 4720 ms |
| `sort_blue_50mm.json` ～ `sort_blue_100mm.json` | 取物、抬起、蓝色前方放置、返回 | 各 8 / 4720 ms |
| `manifest.json` | 来源、哈希、逐帧脉宽、实际选定俯仰与风险清单 | 核对资料，不是动作组 |

共 **20 个动作组、147 帧**。颜色组文件名中的距离是**原程序超声波读数（mm）**，不是夹爪到目标的笛卡尔距离。原代码 `dis / 10` 先做整数除法，再加 `7.6 cm` 偏置，因此保留以下分档：

| 原传感器读数 | 选择文件后缀 | 接近点 X（cm） |
| --- | --- | --- |
| 50～59 mm | `50mm.json` | 12.6 |
| 60～69 mm | `60mm.json` | 13.6 |
| 70～79 mm | `70mm.json` | 14.6 |
| 80～89 mm | `80mm.json` | 15.6 |
| 90～99 mm | `90mm.json` | 16.6 |
| 恰好 100 mm | `100mm.json` | 17.6 |

原代码只处理 50～100 mm；其他读数没有对应动作。分档沿用原程序行为，不表示精度足够或超声波偏置适合当前安装。

## 来源与转换方式

主要来源位于 `E:/26FPGA/prj_v1.0/color_sorting_referrence/05_color_sorting/51/LeArm_C251/`：

- `User/main.c`：准备、接近、夹紧、抬起、三色放置、松爪、返回及传感器触发条件。
- `User/global.h`：PWM/BUS 类型选择和六轴复位脉宽 `[770,1500,640,511,1255,1500] μs`。
- `Hiwonder/Arm/src/robot_arm.c`：夹爪 `servoAngle=90-openAngle`、腕转、坐标调用与原厂动作组存取逻辑。
- `Hiwonder/Arm/lnc/robot_arm.h`、`kinematics.h`：俯仰范围、几何尺寸和运动学约定。
- `Hiwonder/Peripherals/src/pwm_servos.c`：原厂角度到 PWM 的映射及最短运动时间 20 ms。

已遍历参考目录的 C/H/Python/JSON/ROB/XML 文件并在 `manifest.json` 中保留清单和哈希。参考目录内没有可直接迁移的成套姿态 JSON；动作来自上述 C 代码。SDK 压缩包中的相关 JSON 主要是模型、调试及上位机格式审计数据，不能作为原厂固定动作库。`.build-learm-audit/sample_pwm.rob` 是格式样例，不作为实测动作。

手柄和上位机的实时点动依赖输入，不生成固定动作；旧控制器 Flash 中已下载动作的实际内容未提供，不能从存取函数恢复。编译产物不当作额外动作库。原 `kinematics.c` 源文件缺失；本项目已有运动学根据原编译清单恢复约定并重写，不能声称解支与原控制器逐位一致。

使用 **`sdk_v1.0/arm_servo_linux` 现有 C++ 运动学和 MockBackend** 计算端点、执行每 20 ms 的插值并记录实际量化命令。JSON 格式原样兼容 `ui_app/arm_actions.cpp`：

```json
{"version":1,"frames":[{"anglesDeg":[0,0,0,0,0,0],"durationMs":1000,"holdMs":0}]}
```

上例仅解释格式，不是安全姿态。数组顺序为 **夹爪、腕转、关节3（腕俯仰）、关节4（肘）、关节5（肩）、底座**，不是原厂内部倒序的 `pwm_servos[]`，也不是从底座向上排列。

| 顺序 | 阶段 | 目标 | 运动 / 停留 |
| --- | --- | --- | --- |
| 1 | 准备 | `(12,0,0) cm`，夹爪采用复位角，腕转采用 1500 μs 模板值 | 500 / 0 ms |
| 2 | 张爪 | 原厂 openAngle=90，对应项目夹爪角 0 | 20 / 0 ms |
| 3 | 接近 | `(dis/10+7.6,0,-7) cm`，保持夹爪与腕转 | 1000 / 0 ms |
| 4 | 夹紧 | 原厂 openAngle=0，对应项目夹爪角 90 | 200 / 0 ms |
| 5 | 抬起 | `(15,0,15) cm` | 1000 / 0 ms |
| 6 | 放置 | 红 `(5,12,-5)`、绿 `(5,-12,-5)`、蓝 `(27.6,0,-5) cm` | 1000 / 0 ms |
| 7 | 松爪 | 项目夹爪角 0 | 20 / 480 ms |
| 8 | 返回 | `(12,0,0) cm`，保持张爪 | 500 / 0 ms |

原程序启动时复位、坐标、张爪命令连续下发，缺少等待，可能互相覆盖。这里将复位单独导出；分拣组从准备开始，并明确串行执行张爪。原 `time=0` 在舵机驱动中会变成 20 ms，松爪阶段用 20 ms 运动加 480 ms 停留保留原 500 ms 的名义预算。视觉确认、距离复测等待和无限循环没有写入动作组，界面调度还可能增加实际耗时。

## 必须知道的风险与问题

1. **当前实机校准不足，原厂夹爪范围尤其不适用。** 项目现场记录只验证过夹爪约 920/1040 μs 的候选工作点、腕转部分范围；这些 JSON 沿用模板，夹爪仍会要求 500/1500 μs，复位还包含 511/640 μs 等接近端点的命令。存在过夹、堵转、撞限位、拉扯线缆和损坏舵机的风险。
2. **正常映射和全范围调试映射不同。** 本批文件按仓库 `arm_config.ini` 模板的正常映射生成（夹爪 0～90° 对应 500～1500 μs）。当前 UI 的全范围调试会把夹爪改成 0～180° 对应 500～2499.2 μs，同一个 90°只得到约 1499.6 μs。其他实测方向、偏移、通道、限位变化也会改变动作效果。需按最终配置重新转换和校验，不能靠加载成功判断兼容。
3. **可达点不代表要求的工具姿态成立。** 原要求的 0°俯仰只是偏好；准备姿态实际约 -64.09°，50 mm 分档接近姿态约 -85.80°。最大偏离约 **85.80°**。多帧还落在数学关节限位（例如肘轴角 0°）上，未保留实机安全余量。夹持方向、桌面间隙和抓取效果可能不符合预期。
4. **没有碰撞或轨迹规划。** 正解只校验端点坐标；关节线性插值的中间路径可能碰到桌面、机械臂自身或物体。抬起到放置、任意当前位置到第一帧都需要检查，负 Z 目标也不保证在当前桌面之上。首帧会同时指定六轴，不能假设只移动坐标关节。
5. **量化与原厂输出不同。** 原厂采用 500～2500 μs 并截断整数，本项目采用 500～2499.2 μs、步长 7.84 μs，并限制量化后的命令在轴限位内。模板夹爪 1500 μs 的实际名义输出为 **1495.68 μs**；本批动作端点仅因名义量化造成的最大位置误差约 **0.20048 cm（2.005 mm）**，还不包括舵机间隙、几何误差、负载或电气时钟误差。原控制器 Flash 的舵机偏移未知，这里使用模板零偏移。
6. **静态动作不会自动确认颜色、距离或是否抓住。** 文件选择必须匹配实际物体位置；播放到时就进入下一帧。软件“到位”只是命令插值结束，没有位置、接触、夹持力或电流反馈。原厂颜色/超声波判断和当前识别服务没有接入这些文件。
7. **JSON 本身不阻止误播放。** 当前加载器只检查格式、帧数、角度和时间范围，不检查来源哈希、映射指纹或 `hardwareValidated=false`。`manifest.json` 是审计材料，不是执行保护。UI 再保存动作会只保留 `version/frames`，需要保留本说明和清单。
8. **上机前仍需现场条件。** 先完成各轴方向、零位、机械范围、夹爪工作点与连杆尺寸的校准，再逐帧慢速核对空载轨迹。停止并保持会继续输出 PWM；关闭 PWM 可能失去保持力。准备支撑和可切断舵机电源的急停，不能把软件状态当成实际停波测量。

## 离线检查与再生成

在 `E:/26FPGA`，使用 Python 3 和 PATH 上的 g++：

```powershell
python sdk_v1.0/ui_app/tools/generate_learm_actions.py
python sdk_v1.0/ui_app/tools/generate_learm_actions.py --check
```

生成器只支持这份已核对的模板映射，检测到主要源动作、复位脉宽或映射变化时会报错，要求重新审阅转换。不会覆盖板端配置。每次先在临时目录编译 MockBackend 导出工具，全部生成并验证成功后才发布 JSON。

本次检查通过：20 个动作组的 JSON 数值/帧数/时间/轴限位，147 帧的模拟插值和量化输出，坐标端点 FK 回算，以及项目原有关节控制、运动学/控制器测试。**未运行 Qt 加载器程序或实机动作测试**；生成格式按现有 `ArmActions::load` 的字段和约束核对。

界面可在模拟模式通过“机械臂控制 → 动作组 → 载入 JSON”选取上述动作文件。`manifest.json` 仅供核对，不应在该对话框中作为动作加载。本目录保存于当前工作的 `sdk_v1.0`，未覆盖 `prj_v1.0/sdk` 的旧副本。
