# 2026-10-24 联动代码检查与修复

检查范围：传送带控制库、UI 与机械臂动作队列的交接、视觉数据消费和新 AXI 分流/编码器 RTL，并复核原工程时钟约束。未对 SDK 内所有第三方库进行逐行审计。

## 已修复的问题

1. **P1：手动抓放确认窗口存在状态竞争。** QMessageBox 等待期间仍处理控制定时器，传送带可能已停机或故障；旧逻辑在确认返回后先提交机械臂队列，再尝试进入 Picking。现改为确认后重新检查带面、机械臂和观察姿态，先成功锁定 Picking，再提交动作；提交失败会停止本次队列和带面。
2. **P1：手动动作中断可能被当作完成。** 原手动分支只检查“不运动且队列不活跃”，可能在操作员停止后触发自动放行。现机械臂统一记录 actionJobId/actionJobState，传送带只接受属于本次任务的 completed；中断、失败和任务被替换均停机，不放行。
3. **P1：抓取期间带面缓慢漂移可能漏检。** 摄像头随机械臂移动时暂停视觉读取，原编码器检查仅限制速度；低于稳定速度门限的漂移仍可累计。现记录进入 Holding 时的编码器基准，在 Holding/Picking 累计净位移超过定位容差即故障并停机。此检查依赖现场正确标定 cm_per_count。
4. **P2：硬件进料的启动条件过晚。** 现硬件进料必须开启视觉，真实自动分拣还须在进料前通过普通模式关节标定、几何确认和坐标映射兼容检查；不等物体到线后再拒绝。

涉及文件：`conveyorpage.cpp/.hpp`、`armpage.cpp/.hpp`、`../conveyor_linux/conveyor.cpp/.hpp`。未修改物理引脚、机械臂生产校准值或分类模型。

## 仍未解决、不能当作可实机运行的部分

- **PL 主工程时钟与时序仍阻塞发布。** 厂方原始数据库在当前 TD 下也出现 PLL/PS 接口被误按 50 MHz 分析；修复厂方工程路径后仍复现。关闭自动 IP 时钟建模或仅添加同名虚拟时钟会使接口失去有效分析，不能用其正裕量发布。详见 `../../../prj_v1.0/soc_prj/doc/conveyor-timing-audit-20261024.md`。
- 新传送带 PL 仍是 BENCH_ONLY，物理输出硬锁低且未引出；本轮没有刷新 BOOT、DTB 或 FPGA 位流，没有做新总线板上自检。
- 带面/编码器实测、厘米标定、滑行与负载停稳误差、机械臂现场路径和五类放置点、移动摄像头曝光/读出延迟保护值均待机构就绪后验证。模拟结果不能代替定位精度或抓取成功率。
- 机械臂没有位置反馈；软件“completed”表示命令序列完成，不能证明已经夹住物块或实际到达位置。原舵机 PL 在进程异常退出时也不提供独立运动确认或硬件急停。
