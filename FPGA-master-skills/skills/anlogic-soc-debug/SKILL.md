# 安路 SoC 联调与故障定位

把现象定位到硬件、平台初始化、驱动或应用的具体边界，再修改最小范围。支持无硬件时的静态核对；历史 demo 的成功不等于当前工程通过。

## 固定现场

记录器件/板卡版本、运行方式（裸机/Linux）、加载方式（JTAG/持久启动）、硬件 HPF/bitstream、APP/FSBL、内核/DTB/rootfs 的来源与散列。先取启动日志或第一次失败的错误；保存复现步骤、输入、预期/实际、发生频率。对照当前 `.al/.hpf/system.mss`、地址头文件、链接脚本和 DTS，避免在旧平台与新 PL 混用时继续改驱动。

如果有串口，先动态确认当前设备与占用程序；`putty-dr1m90-serial` 可帮助识别 CH342 控制台。串口、JTAG 和网络属于不同通路。没有串口输出不能单独证明 CPU 没启动，没有设备节点也不能单独证明 PL 没配置。

## 选择第一条断点

| 现象 | 优先读取 | 证据和下一步 |
|---|---|---|
| 无启动/卡在 FSBL 或 U-Boot | [启动与系统排障](references/boot-runtime.md) | 最后一条可信日志 → 确认对应镜像/初始化/介质阶段 |
| 寄存器读全 0、全 1、访问挂住 | [AXI 与中断](references/axi-irq.md) | 地址/时钟/复位/译码 → 一次最小读事务及响应 |
| DMA 完成却数据错、偶现旧帧 | [DMA 与缓存](references/dma-cache.md) | 地址和缓冲区所有权 → 连续性/长度/宽度 → cache维护 → 数据布局 |
| 中断无响应或风暴 | [AXI 与中断](references/axi-irq.md) | PL源 → 路由 → 控制器 → OS映射 → 触发/清除 |
| 驱动未 probe、模块失败或应用崩溃 | [启动与系统排障](references/boot-runtime.md) | 运行内核/DT/ABI → 绑定/资源 → 用户态依赖 |

多条路径同时可疑时，优先检验能排除最多原因、且对运行状态影响最小的假设。每次记录“证据→假设→一次验证→结论”；不要用无边界重启、改延时、关闭 cache 的方式掩盖故障。

## 保持测试有判定力

读取有副作用的寄存器前先查描述：clear-on-read、FIFO pop、W1C/读改写等行为不适合盲扫。寄存器地址和存储范围必须由当前工程确认。上板下载、复位、驱动卸载和写盘按用户当前任务授权执行；仅整理、分析日志时不顺带改变硬件。

完成时给出：根因及支持证据、修改点、原始用例回归、涉及的边界用例、剩余风险。没有证明的猜测保留为假设；若未上板，交付可执行的最小验证步骤和所需信号/日志。

资料来源和已发现的教程矛盾见 [来源与边界](references/sources.md)。
