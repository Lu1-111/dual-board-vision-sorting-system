# DMA、内存与 cache 一致性

## 每块缓冲区必须只有一个当前写入者

先明确数据方向与所有权：CPU 产生 → device读取；device产生 → CPU读取；或者环形队列中的明确 slot 状态。描述符、payload、长度和完成状态各自可能有缓存问题，不能只维护 payload。

资料事实：[D1] 4789–4814、4842–4848 行演示 CPU 写后 flush、设备写完成后 CPU 读前 invalidate，并提醒总线位宽和时钟转换。该教程只覆盖一个示例，不足以定义多核/并发/双缓冲场景。

当前工程头文件 [P1] 将 `AlCache_FlushDcacheRange`、`AlCache_InvalidateDcacheRange` 的参数定义为 `(Start, End)`，不是 `(address, length)`；传入结束地址前验证范围计算无溢出。**同一头文件说明 invalidate 遇到 dirty cache line 会先 flush**，所以它并不保证“丢弃旧脏数据而不写回”。不要在 device 已写入新数据后，让 CPU 旧脏行通过 cache 操作覆盖新数据。

## 裸机工程的正确性核对（工程建议）

- CPU→device：在交出所有权前写完数据/描述符，按当前 SDK 语义清理相关 cache 行，完成所需内存排序，再触发 device。传输期间 CPU 不修改同一缓冲区。
- device→CPU：交给 device 前完成该缓冲区旧脏行处理，传输期间 CPU 不写入；确认 device 写入已完成及可见，再执行适配该 SDK 的 CPU 取回操作并读取。完成信号必须真实代表数据落到规定边界，而非仅收到开始命令。
- 为 DMA 缓冲区按**当前平台的 cache line**对齐并独占整行，避免同一行含无关对象；对齐扩展范围后也不能越过合法内存。不能用固定 32/64 字节替代对当前 CPU/SDK 的检查。
- 使用双缓冲/环时，记录状态 `free → filling → ready → consuming → free` 和序号；先从单缓冲、单次传输验证，再扩大流水。不要靠增加 delay 掩盖所有权竞争。
- 多核共享时另外确认核间同步、内存属性、屏障和缓存一致性；`volatile` 不会把普通 HP DMA 变为一致性访问。
- 关闭 cache 可以作为有界定位实验，但不能作为已解决问题的最终证据；恢复最终缓存设置后重测。

不要仅根据头文件注释推断具体 cache 指令、边界舍入和屏障实现；需要时继续读取相同版本 SDK 的实现/反汇编。

## Linux DMA 路径（工程建议）

Linux 中以运行内核的 DMA mapping API 和设备约束管理 DMA 可见地址。区分 CPU virtual、CPU physical 和 DMA/bus 地址，不能对用户态 buffer 做强转得到 DMA 地址。先确认 DMA mask、实际连线可访问范围、连续性/散列表支持及是否存在 IOMMU。

按设备需求选择一致性分配或 streaming mapping，并严格匹配方向、生命周期与同步；不能把裸机 `AlCache_*` 或 `/dev/mem` 测试直接当作 Linux 驱动实现。CMA、reserved-memory、用户缓冲区固定和映射各有约束，要结合当前驱动与 DT 验证。申请成功不等于 PL master 能覆盖该地址位宽。

## 区分“传输对了”和“模型/图像错了”

先用固定种子或递增模式，不直接从视频观感判断 DMA。覆盖最小长度、末尾不足一拍、合法最大长度、非整页边界、不同 stride、重复传输和超时。按接口支持情况决定是否允许不对齐，不能用超出协议的地址测试当作正常功能。

| 现象 | 优先核对 |
|---|---|
| 只返回旧一帧、cache开时错 | 所有权、前置脏行清理、完成时序、取回同步、帧序号 |
| 每隔固定字节错 | AXI宽度、WSTRB、字节数/拍数、stride、读出宽度和端序 |
| 尾部错或越界 | 长度单位、burst分割、末拍有效字节、地址范围和对齐 |
| 大地址才失败 | 地址截断、DMA mask、HP可达范围、描述符字段位宽 |
| 只有并发/多核错 | 缓冲区重用、队列/中断竞争、共享cache行与屏障 |
| 字节完全一致但推理结果错 | tensor布局、量化scale/zero-point、RGB/BGR、预处理、输出解释 |

教程 [D1] 4784 行配置64位数据宽度，示例循环却每8字节读取一次32位值（4791–4793行）。这只能抽查部分数据；技能验收应逐字节或按完整有效元素比较全部范围，不能继承这个检查盲区。

NPU 输入/输出也遵守该数据契约。DMA byte-level 一致只证明搬运，量化误差、算子支持和 NPU 图编译需另按模型部署技能验证。
