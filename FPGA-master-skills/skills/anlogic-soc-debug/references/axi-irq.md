# AXI、寄存器与中断

## 先写接口契约

对当前设计列出：PS/PL 发起方、实际 GP/HP/ACP 连接、基地址/窗口长度、寄存器宽度/步长/端序/访问属性、总线宽度与转换 IP、时钟和复位域、中断源/路由/触发/清除方式、DMA 可见内存。

资料事实：[D1] 4690–4721 行按 PS 视角区分 PS→PL Master GP、PL→PS Slave HP/GP、ARM 的 ACP，并写明相关接口的异步时钟关系。端口的 Master/Slave 名称必须连同“相对于哪一侧”描述，避免将方向颠倒。具体位宽、ID、burst 和 outstanding 由当前 PS IP 参数与对应版本手册核对，不从教程表格直接推断某软 IP 端口已配置相同能力。

ACP 的可选一致性能力不能自动推广到普通 HP/GP DMA。使用 ACP 时也要核查事务属性、可访问范围和软件内存属性。[D1] 的示例说明位宽不一致使用 width converter、异步域使用 clock converter；最终以实际连线/时钟报告为准。

## 寄存器读写异常

按依赖顺序逐个排除：

1. 当前 PL 设计是否确实加载；在有版本寄存器的设计中读取其值，并核对构建清单。没有版本寄存器时用受控状态信号和产物来源验证，不用“构建时间新”代替上板证据。
2. PS 初始化是否使能相关总线、时钟、复位与 pinmux；FD 调试是否跳过了必要的 platform init。
3. HPF/TD 地址分配、BSP 生成宏、DTS `reg` 与驱动资源是否一致；确认地址单位、宽度、偏移和映射类型。Linux 里先取得 MMIO 资源并映射，不直接把物理地址强转成普通指针。
4. 在已知无读副作用的寄存器上做单次读验证。写测试只能用文档明确可写且允许破坏的 scratch/测试寄存器。记录期待值、实际值、响应/超时。
5. PL 观测 AXI 时，分别看 AW/W/B 与 AR/R，找出先缺失的握手和返回的 BRESP/RRESP；READY 背压、WLAST/RLAST、WSTRB、burst长度和地址窗口都要与所用接口核对。一次正常握手不证明传输长度正确。
6. 若仅跨时钟或高负载失败，核查转换器、reset release、队列深度和背压。不要通过无依据 false path 隐藏 CDC 问题。

以上握手排查是通用 AXI 工程建议；本技能不凭空给出未知 IP 的寄存器表。示例 `0x80000000`、`0x61000000` 等只是教材中的具体工程数值，不能在另一设计上直接使用。

## IRQ 的四层编号与触发

分别记录：PL 输出位/Concat 序号、SoC 控制器中断 ID、DT 中断描述、Linux 分配的虚拟 IRQ。不要将这四项用一个“中断号”替代。

[D1] 3755–3758 行说明教程使用 16 路 PL→PS 中断；[D2] 6543–6552 的示例把硬件 ID 114 写成 GIC SPI 相对编号 82，形如 `<0 82 4>`。这个转换只适用于对应 GIC DT binding 和选中的 SPI；CPU 型号、控制器类型或绑定变化后需重新确认。Linux 驱动应使用 `platform_get_irq()` 等取得 OS IRQ，不把 114 或 82 传进所有版本的 `request_irq()`。

**教程中存在需要修正的触发描述冲突：** [D2] DTS 示例末项 `4` 在常用 Linux IRQ 定义中表示高电平，而同段驱动（6613–6614 行）传 `IRQF_TRIGGER_RISING`。以当前内核 binding/常量、实际 PL 输出波形和外设清除语义统一为边沿或电平，再验证；不能把这段示例当成两者天然兼容的证据。

### 无中断

- 先确认 PL 确有事件、输出极性与脉宽正确、reset已释放；跨域脉冲是否可靠传递。
- 核对 PL 位映射、SoC mask、CPU 全局中断、ISR注册与驱动 probe 的返回值。裸机样例含 `AlIntr_RegHandler` 与 `AlIntr_SetLocalInterrupt`，签名以当前 SDK 头文件为准。
- Linux 先读取 `/proc/interrupts`，比较受控触发前后计数；确认当前驱动绑定和实际运行 DT，而不是只看源码中的 DTS。
- 计数增长但用户程序无响应：转查 ISR 下半部、唤醒/队列、设备接口及应用等待条件。

### 中断风暴或丢事件

- 核对 pending 与 mask，区分外设端事件清除和中断控制器应答；查 W1C/读清除等语义，不先猜清除顺序。
- 电平型 IRQ 处理后源电平应能退回非有效状态；边沿型确认脉宽、边沿识别与重入/屏蔽窗口。
- ISR 仅完成必要应答和短处理；打印大块数据、长时间轮询或 ISR 断点会改变时序。教程 FD 版本记录过 ISR 断点导致调试异常，应使用计数器/缓冲区在中断外观察。

验收用例包括单次触发、多次触发、背靠背事件、屏蔽后恢复、驱动重载/复位后恢复，并区分硬件事件数与软件处理数。
