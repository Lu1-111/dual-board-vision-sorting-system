# 安路 PL 仿真与板级调试

先把故障定位到“编译/仿真、实现时序、配置链路、时钟复位、业务协议”中的一层，再做最小验证。已有错误日志、波形或工程能回答的问题先读取，避免让用户重复提供。

## 资料入口

本技能以米联客 DR1 快速入门教程和基础示例为证据。当前资料根目录曾为 `D:/PRJ/referrence`；移植时按用户真实路径定位。读 [simulation-and-chipwatcher.md](references/simulation-and-chipwatcher.md) 执行仿真和 ChipWatcher；具体来源、版本与已发现不一致见 [evidence.md](references/evidence.md)。原始手册和完整 demo 没有随此技能复制。

## 首轮定位

记录当前 `.al`、器件/封装、顶层、TD/IP/仿真器版本、board revision、bit 文件路径/哈希/生成时间、启动或下载方式、实际现象与期望。用户只请求日志分析时止于证据与建议；要求修复时继续修改和受影响验证。只对任务需要的层使用工具。

| 症状 | 先取证 | 优先行动 |
|---|---|---|
| 缺模块、IP 黑盒、模型加载失败 | 当前源列表、IP wrapper、compile.f、首个错误 | 修复本次源集/模型，不先修改业务 RTL |
| 仿真波形不变、PLL 不锁 | 仿真时长、refclk、PLL FIN/reset、lock、TB 激励 | 核对频率与复位极性、延长到有依据的观察窗口 |
| 模拟正确而板上错误 | 当前 routed STA/约束检查、实际时钟与 bit 身份 | 排除约束/旧 bit 后再插观测信号 |
| JTAG 识别失败 | 下载器驱动、供电、实际链路识别结果 | 按当前连接核验，不把历史链路型号当本次结果 |
| Watch 等待触发或报错 | 匹配 bit/调试 IP、采样时钟、Trigger Enable/条件 | 先降低触发复杂度建立已知可触发条件 |
| 业务数据偶发错误 | 边界握手/valid-ready、FIFO 状态、状态机、错误计数 | 单次抓取完整因果窗口，定位首次违反协议的位置 |

## 仿真执行

1. 检查目标 demo 自身的 TB 和 RTL，不混用 02/03/04 目录。基础 ZIP 的 03 示例输入频率、PLL 配置和库列表有需要核验的地方 [D2]。
2. 解析 `compile.f` 所需 RTL、IP wrapper/底层模块、include、ROM/RAM 文件和器件模型；仅用“列在清单里”不证明依赖完整。当前 TD 模型目录由安装实际路径决定。
3. 使用教程已证实的 ModelSim `do cmd.do` 流程，检查编译和 elaboration 输出。原 demo `cmd.do` 将 `run -all` 注释掉；DO 运行后没有波形进展时先确认是否真的运行了时间 [D2]。
4. 依据协议增加可自动判断的期望值/断言和超时。时钟、复位、回压、读写边界和 CDC 刺激属于通用验证建议；无关的纯重放测试不增加证明力。只有波形窗口打开不算通过。
5. 保存仿真器版本、实际命令、用例/随机种子、PASS/FAIL 与关键波形。没有可用仿真器或合法模型时保留测试入口并准确报告缺口。

## 实现与在线调试

- 读取本次最终实现报告及 check_timing，先检查时钟和约束覆盖再看 slack；必要时调用当前可用的 `anlogic_td.project_info/build_project/job_status/read_job_log/list_reports/read_text_file`。MCP 的构建成功不证明时序闭合，也不证明 bit 已下载。
- PLL/复位先看参考时钟是否运行、reset 极性、lock、各域 reset release。DR1 PLL 原语 `pllreset` 高有效；业务名 `_n` 不能代替实际连线证据 [D3]。复位同步和 CDC 结构审查属于通用方法，不能声称某个未知 TD CDC 命令已经检查。
- 需要芯片内部波形时，在目标 IP Catalog 生成 ChipWatcher，以当前生成 wrapper 连接采样时钟和 probe。一次只选能区分当前假设的状态、握手、计数器与错误信号。按参考完成生成、重新编译、时序检查、下载匹配 bit、设置触发与采样。
- 下载前核对当前目标板/链路、器件、文件与任务范围。用户已要求上板测试时继续执行范围内的下载；闪存固化、格式化 SD 或重做启动镜像是额外动作，需要相应任务授权，不从普通调试请求推导。
- GUI 操作需使用当前可用计算机控制能力或由用户操作；当前 `anlogic_td` MCP 未提供下载/ChipWatcher 捕获专用接口。不要虚构自动捕获 API，也不要将 PS 串口回显当作 PL 已烧写的证明。

## 结论与复验

每次只提出能够被下一次观测区分的主要假设。修复后复现原失败输入，再验证邻近边界；新增 ChipWatcher 后重新比较资源和最终时序，因为探针本身会改变实现。

输出故障触发条件、最小复现入口、根因证据、修改文件、仿真/STA/板测分别完成到哪一步，以及仍待确认项。只有实际捕获或读回能支持的硬件行为才写“已验证”。保留与该结论匹配的 bit 身份和调试配置，避免用旧波形说明新 RTL。
