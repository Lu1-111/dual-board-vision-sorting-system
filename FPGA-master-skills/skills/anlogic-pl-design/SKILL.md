# 安路 PL 设计与实现

将用户的接口/逻辑需求落实为可综合 RTL、匹配硬件的约束、仿真证据和实现报告。优先沿用目标工程的器件、IP 版本与构建入口；仅在需求要求时新建工程。

## 适用证据与入口

本技能已核验米联客 DR1 教程、基础 demo 和 DR1 PLL/IO 手册。证据是版本相关的参考，不证明任何其他器件/板卡兼容。资料位于用户提供的资料根目录，当前会话曾为 `D:/PRJ/referrence`；迁移后先定位资料根目录，不要求这个盘符存在。详细来源和勘误见 [evidence.md](references/evidence.md)。

- 约束、TD 构建或时序问题：读 [constraints-and-build.md](references/constraints-and-build.md)。
- 查器件管脚/电压/时钟能力：按 evidence 中对应手册定位章节，并核对当前板卡原理图。不要把 demo 的 H16/T19/R19 或 DR1M90GEG400 当成默认配置。
- 需要仿真或上板观测时，可使用同包的 `anlogic-pl-debug`；该技能缺失时，仍可使用目标工程现有测试和 TD 报告完成可做的部分。

## 执行流程

1. **读现有工程和规格。** 发现 `.al` 后读取 Family、Device、Speed、TOP_MODULE、源文件/IP/ADC/SDC、活动 synthesis/implementation run。记录实际板卡与修订号、端口方向与位宽、吞吐/延迟、时钟频率及关系、复位极性、外设时序。现有文件可回答的问题直接读取；缺失硬件信息不妨碍先实现纯逻辑，但不得臆造引脚和电平。
2. **确定 RTL/IP 边界。** 对 PLL、RAM/FIFO、DSP、IO 原语优先检查目标 TD IP Catalog 和项目已有生成物。保留 IP 配置、wrapper、RTL、初始化文件和仿真模型之间的版本对应；从当前 IP 的例化模板取端口，不根据旧例程重写原语签名。不要只复制 `.v` 后遗漏 IP 元数据或 ROM 初始化文件。教程“Show Instantiation Template”的路径和工程文件类型有证据 [E1, E2]。
3. **设计时钟/复位和跨域。** 建立时钟域表，写明时钟来源、目标频率、复位断言/释放条件及每条跨域通道。DR1 `pllreset` 为高有效，`lock` 指示 PLL 锁定 [E4]；wrapper 端口名称不保证极性，必须沿连接核验。下列为通用 RTL 工程建议：复位按各目标域同步释放；稳定单比特用同步器，脉冲用握手/脉冲同步，多位相关数据用握手保持或异步 FIFO；不能把每位各过两拍视为总线一致性保证。同步结构与 STA 例外分别评审。未核验 TD 版本的专用 CDC 命令时，不声称已执行工具 CDC 检查。
4. **实现并仿真。** 写明寄存器/组合逻辑、计数边界、算术符号与位宽、溢出行为。自检 testbench 覆盖复位、边界、背压及协议次序；有多个时钟时改变相位关系。安路原语仿真必须使用该器件/版本模型，不能仅靠通用仿真器解析通过宣称 IP 正确。保存编译输出、断言结果和复现入口。
5. **建立约束。** ADC 管物理 IO 位置/电平等属性，SDC 管时钟与时序关系；这里的 `.adc` 是约束文件，不是模拟 ADC 外设。按实际原理图和外设数据表填写 location、bank VCCIO 与 IOSTANDARD。由 `T(ns)=1000/f(MHz)` 校验周期，核对 PLL FIN、testbench、SDC 三者一致。教程存在 25 MHz/10 ns 文字矛盾，不能照抄 [E1, E3]。参考详情后再添加生成时钟、接口延迟和确有依据的例外。
6. **分阶段构建。** 在当前 MCP 提供时用 `anlogic_td.project_info` 检查工程，再使用 `build_project(stage="elaborate"/"synthesis"/"implementation"/"bitstream")`；选择与器件对应的数据库和工程中的 run。轮询返回的 job，读失败日志的首个根因。无 MCP 时用已安装 TD GUI 或该版本已验证的 Tcl 流程；不猜测其他 FPGA 厂商的 Tcl 参数。具体调用和报告路径规则见参考。
7. **依据报告修正。** 实现成功后读取最终 routed 时序、check_timing、例外、资源和时钟使用报告。先处理缺时钟、无效约束、PLL 频率冲突等，再诊断 setup/hold 路径。通用优化建议：逻辑深度高时分流水；高扇出/布线占比高时考虑布局、局部复制和流水；修 hold 时以工具报告为据。每次改动重验功能与时序，不通过放宽时钟或无依据 false path 掩盖需求失败。

## 完成标准

交付实际修改文件、顶层与目标器件、时钟域表、IO/时序约束依据、仿真结论、构建状态及报告位置。若用户要求时序闭合，必须给最终 routed 报告的 setup/hold 统计、检查角、未约束/例外项和对应时钟。正 slack 或 bit 生成成功本身不足以证明完整时序闭合；基础 demo 的正 slack 同时伴有 83.13% STA coverage 和两个无 output delay 的 LED 端口 [E6]，应逐项解释而非照搬豁免。

运行过什么就报告什么。未接板时标明“未上板”；未安装仿真器/模型时明确验证缺口并保留可运行入口。编译和生成 bit 不等同于下载或固化；后两者按用户任务范围执行，不在本技能中自动扩展。
