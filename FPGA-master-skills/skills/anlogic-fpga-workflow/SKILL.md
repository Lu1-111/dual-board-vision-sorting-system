# 安路 FPGA / FPSoC 开发入口

基于米联客 F3P-CZ02 / DR1M90 资料与本地 TD/FD 接口。其他安路系列可借用方法，但必须重新确认器件、IP、软件版本及板级连接。不要把 DR1M90 的资源、地址、引脚和 NPU 约束外推到整个安路产品线。

## 先冻结实际目标

从用户任务、工程与板卡证据记录：板卡/PCB/器件型号与版本，TD/FD/SDK版本，当前工程与top，时钟/复位，启动介质和运行系统，外设接线，性能/精度目标。仅缺少会影响实施的字段时再向用户询问；能从工程和资料读取的先读。

资料根目录由用户或当前工作区发现，历史位置为 D:/PRJ/referrence（名称确实拼作 referrence）。按 [资料导航](references/reference-map.md) 选择章节。示例目录、旧版本手册与实机状态可能不同，记录来源与版本，冲突时以同版原理图、生成配置和可复现实验交叉确定。

## 集成时必须对齐的契约

1. PL导出的硬件描述、FD平台/BSP、应用的寄存器基址/中断、Linux设备树和实际位流来自相容版本。变更PL接口后重新检查这条依赖链，不能仅重编APP。
2. AXI控制寄存器定义位宽、复位值、访问属性、单位、写1清除/读清除和busy/done握手；流接口定义valid/ready、帧/行边界、背压、时钟域与缓冲区所有权。
3. DMA缓冲区区分CPU虚拟地址、物理地址和设备地址；按实际OS/SDK维护cache和屏障，中断由软件确认源头并清除。跨时钟域使用适当同步/异步FIFO，不能给所有路径加false path来消除报错。
4. NPU模型、HardNPU/SoftNPU配置、驱动/runtime及输入输出布局/量化规则一并冻结。需要CPU或PL执行的节点必须显式划分并计入总时延。

## 完成标准

按请求范围提交实际完成的证据，区分：静态检查、仿真、工具构建、时序报告、上板功能、模型任务指标和端到端性能。没有板端测试时标明未上板；MCP成功和生成bit/ELF仅证明对应构建步骤结束。

建议交付一张产物表：源版本、器件、硬件描述、bit、ELF/启动镜像/DTB/rootfs、模型/runtime、SHA256、验证条件与结果。只为本次请求所需对象收集，不要求每次小改动都跑全链。

刷写启动介质、恢复出厂、复位板卡或切换运行程序仅在当前任务已包含这些操作时执行；生成/阅读文档与打包本身不触发硬件操作。
